# Software Architecture Trade-offs

This repository documents studies and practical reflections about software architecture decisions, focusing on trade-offs between functional and non-functional requirements.

## 🎯 Purpose

The goal of this repository is to explore how architectural decisions impact:

- Performance
- Security
- Scalability
- Maintainability
- Business constraints (time-to-market, cost, risk)

Software architecture is not only about making systems work — it is about making them sustainable.

---

## 📌 Core Concepts Studied

### 1. Functional vs Non-Functional Requirements
- Functional Requirements → What the system does
- Non-Functional Requirements → How the system behaves

Understanding the balance between both is critical to avoid architectural failures.

---

### 2. Quality Attributes

Key attributes explored:

- Performance
- Scalability
- Security
- Reliability
- Maintainability
- Usability

Each attribute introduces trade-offs that must be evaluated in context.

---

### 3. Architecture and Business Pressure

Architectural decisions are influenced by:

- Time-to-market
- Budget constraints
- Market expectations
- Product lifecycle

Balancing technical excellence and business needs is a core engineering skill.

---

- Separation of Concerns (SoC)

- Low Coupling and High Cohesion
- Layered Architecture
- Microservices
